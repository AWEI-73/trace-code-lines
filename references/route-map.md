# 路線動態圖

按需求產出。代理讀註解、說明文件與原碼寫白話路線；工具核對位置、自動排版，不自行宣稱功能意義。

## 操作

1. 先用 derive-map.mjs 產生地圖，用 report.mjs 產生健檢。
2. 寫設定檔：所有路徑相對於設定檔。

```json
{"maps":["map.json"],"health":"health.json","routes":"routes.json","outDir":"route-output"}
```

3. 產生候選草稿：`node scripts/route-map.mjs candidates --config route-config.json`。
4. 代理挑選、讀檔並命名，寫 routes.json。候選檔不能直接顯示。
5. `node scripts/route-map.mjs render --config route-config.json` 產生 route-map.html、routes-checked.json、route-report.md。舊的健檢、報告與流程圖不變。

## 路線檔格式

```json
{
  "schema":"routes-v1",
  "title":"程式路線",
  "stations":[
    {"id":"entry","name":"受理需求","file":"main.mjs","block":"入口","inferred":false},
    {"id":"store","name":"保存資料","file":"store.mjs","block":"資料","inferred":true}
  ],
  "routes":[{
    "id":"save","name":"保存需求","description":"受理後交給保存程式。",
    "hops":[{"from":"entry","to":"store","action":"載入保存程式","anchor":{"file":"main.mjs","line":1,"expect":"./store.mjs"}}]
  }]
}
```

每站必須有唯一 id、白話 name、相對於受查專案的 file、白話 block、布林 inferred。沒有命名線索時 inferred 設 true，站名旁顯示「推測」。站名與區塊名最多 36 字；其他主要文字最多 120 字。

每路線有唯一 id、白話 name、一句 description、不為空的 hops。每段 from/to 對應站 id，上段 to 必須等於下段 from。action 說明這次引用的動作。anchor.file 必須是出發站的檔案，line 從 1 起算，expect 是該行非空字串。

## 核對與顯示

- 原檔、行號或字串錯誤：整條路線不顯示，記錄在 route-report.md 限制與 routes-checked.json。
- 原文正確，且 derive-map 閉包或 gasAnalysis 中有相同出發檔、到達檔及引用行（含 sites）：實線。原文正確但缺連線：「人工判讀」虛線。這是允許顯示的有限結果。
- 健檢問題依代表檔、目標檔與見證檔對應站點；孤兒群組依檔案成員對應。直接沿用問題卡的白話文字，不加寫新結論。
- 主要文字沿用 assets/plain-language.json 禁用詞，不接受英文術語。檔名行號放在步驟的灰色小字。
- 手機寬度小於 600，全部有效路線的唯一站點超過 18 個時，選路線只畫單線；全部顯示區塊與區塊間粗線。寬度至少 900 時左圖右步驟。
- 單檔離線並支援深淺色、鍵盤選站與減少動態偏好。不載入外部資源。

## 限制

線表示程式碼裡有這條引用，不代表實際執行過。引用不等於呼叫時序，流動光點只是閱讀導引。手工動作說明仍需代理對照原碼。

候選使用每入口的有界廣度搜尋，最多 12 段、40 條路線，只保留第一條到達路徑；迴圈、同目標其他路徑會省略，截斷記在 limits。代理可依原碼另寫路線。工具不執行受查專案、不追蹤符號連結、不用候選推定部署與功能完成。

## 自動排版

每條路線的入口深度為 0，每段加一；同站多次出現取最淺深度。同層依相連站的位置調整順序，減少線交叉，不保證全域最少交叉。每排最多三站；放不下或同排直線會穿過第三站時拆成相鄰排。邏輯深度不變，畫面顯示層可因拆排下移。

往下的線從出發站底邊接到目標站頂邊，使用三次曲線；同排水平直連。跨多排時優先使用弧線或站框間的空隙避讓；仍會穿站或路線往回走時，再從較近的側邊以曲線繞過；回頭線從站頂離開。手機站名保持 15px。超過十八站時的選定路線仍是單欄直線。

區塊總覽將相鄰的同區塊站合併後排層，不補造跨區塊連線。同方向連線依所有有效路線內出現的段數加總（同段在不同路線重複出現也計數）：1 段為 2px、2～3 段為 3px、4 段以上為 4px。最粗是 1.6px 站框邊線的 2.5 倍；這不是執行次數。沒有跨區塊邊的區塊仍顯示，框下註明「這條路線沒有接到其他區塊」。所有模式的箭頭均使用 userSpaceOnUse 的 8×8 單位，不隨線寬放大。

## 選中路線的排法

選中路線時，手機與桌機都依段落順序，將每站第一次出現的位置由上到下排成置中單欄。只畫這條路線的站，圖上方說明站數與回到「全部」的方法。相鄰站以垂直直線連接；重訪站只畫一次，回頭線從側邊繞回，步驟清單仍列出每一段。

路線之間切換時，同一站用 0.35 秒平滑移到新位置；開啟 prefers-reduced-motion 時不做過渡。「全部」的分層圖與區塊總覽排法保持不變。

回訪後再前往新站，若需跨越已畫的站，也使用側邊通道避開站框。

## 1.15.3 站框與收放

- 預設顯示全部，保留原有拓樸與層次。
- 站框寬度依兩行文字估算，最小 96px，最大為圖寬 80%；全部模式另受原有每層三站空間限制。高度 40px 起，長名稱換行不截斷，點擊範圍至少 44px。
- 再點同一路線，或點圖上的「展開全部」，即回到全部；步驟與說明同步切換。
- 收合先淡出 200ms，再移動 350ms；展開先移回 350ms，再淡入 200ms。路線間直接移動，連線跟隨站位。
- 連點取消前一過渡，從當前位置接續；減少動態偏好下直接切換。
