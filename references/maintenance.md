# 維修單：原因、判定與試跑對照

維修單同時列出靜態異常與已觀測的執行失敗。前者保留原始分類，後者另成維修項目；不以覆蓋同一個檔案推定失敗原因。故障分組只表示相同的觀測邊界，不表示已找到根因。

## 操作與輸入

先用原有 derive-map 設定產生正式與測試地圖，再執行 report.mjs。maintenance.decisions 可提供讀碼者的判斷；maintenance.waterSources 每筆有 report、config、snapshot 三個參照，均含 path 與 sha256。來源清冊格式為 {"repo":"/isolated/repo","files":[{"path":"src/main.mjs","sha256":"<actual hash>"}]}。試跑前保存來源清冊，試跑後核對。報告程式只讀來源與證據，不執行受查程式。

範例：
```json
{
  "maintenance": {
    "decisions": "decisions.json",
    "rerunPrerequisites": [["node", "scripts/build.mjs"]],
    "waterSources": [{
      "report": {"path":"water-source.json","sha256":"<actual hash>"},
      "config": {"path":"scenarios.json","sha256":"<actual hash>"},
      "snapshot": {"path":"source-snapshot.json","sha256":"<actual hash>"}
    }]
  }
}
```

rerunPrerequisites 必須由該專案實際準備流程取得；上述建置命令只是設定格式範例，不是所有專案的預設步驟。設定不授予執行權限。

## 靜態異常的合併

基本鍵為「類別、引用或寫入檔案、確切行號、目標區塊」。沒有區塊時以完整目標路徑分開。產生檔以已找到的寫入位置為鍵，保留消費端位置。

同檔 JavaScript 採有界詞法分析：追蹤頂層單一變數的 =、+= 指派及其引用；同類別、同目標區塊的讀取，只有到達共同字面寫入位置才合併。保留 mergeWriters；不同檔案、類別、區塊或獨立寫入不合併。未知運算、跨函式與跨檔資料流不猜測。「出現幾處」是來源檔、行、目標的去重數，可能大於原始異常數。

## 執行失敗的合併

從已綁定的錄帶讀取完整標準輸出與錯誤輸出。TAP 逐筆取 not ok 的診斷，遇到診斷終止或下一個結果即停止；排除 SKIP、TODO 及僅彙總子測試失敗的套件列，避免把後面的環境拒絕誤算到前面的產品失敗。多行錯誤保留實際值與預期值。

最早位置是 stack 第一個專案內的 file:line；略過 Node 內建位置與專案外路徑。沒有 stack 時用該筆測試位置；仍缺少就明寫缺口，不捏造根因位置。

以以下任何一個相同鍵建立連通群組：
- 相同的完整錯誤訊息；
- 相同的具體錯誤碼；
- 相同的最早專案位置；
- 診斷明寫相同的被拒絕 action。

ERR_TEST_FAILURE、ERR_ASSERTION、AssertionError 等框架通用碼，以及只說 test failed、failure 或通用斷言標題的訊息，不單獨作合併鍵，避免把所有故障混成一件。具體訊息仍可包含這些框架名稱。無可用鍵時依執行與測試名稱分開。此規則不讀答案，不依專案名、路徑名單或特定錯誤特例分組。

每組單獨標「壞了」，列失敗測試數、失敗情境數、代表錯誤、最早位置、可用的重跑命令及證據識別碼。非零退出但沒有可解析測試列時，保留為一件程序／情境失敗；有環境拒絕則另列。退出成功但情境的狀態斷言失敗，也列為產品失敗。觀測、清理或覆蓋缺口本身不冒充產品故障。非 TAP 的既有分類保留產品失敗摘要；不宣稱完整解析所有測試框架。

只有失敗 stack 或測試位置確實出現在靜態異常的來源檔案內，才互相連結。即使有連結，失敗仍保留獨立維修項目；不把整次 TAP 掛到一張有覆蓋但不相關的卡片上。

環境拒絕另列，不計入壞了；同一次執行同時有產品失敗與環境拒絕時，兩類各自保留。

## 確定斷線與人工判定

原始分類 broken 且字面目標缺於來源清冊、引用行可讀、該行字面值可解析到缺少的目標時，機器直接保留「壞了」，產生來源錨點。人工未填判定、未填修法或提出 unsure 不會蓋掉已核對的斷線。主畫面列出缺少目標、引用位置、包含引用檔的入口閉包及驗證方法。找不到入口閉包就明寫缺少路線證據。

若引用行或目標關係無法核對，標「不確定」並列缺口。generated、redirect 或一般可疑跨區依賴仍依其實際證據判斷，不自動當作缺檔。

人工判定規則：
- handling：具體風險、來源錨點與可核對的修改位置。
- fine：文件／註解的意圖錨點，或成功且已清理、異常行有正計數的試跑。
- broken：核對過的斷線，或位置直接相關的產品失敗。
- unsure：證據不足，明寫缺什麼。

錨點包含 file、正整數 line、非空 expect；機器確認該行包含 expect。人工判定缺錨點或修法時可降級；這不撤銷獨立成立的機器斷線或執行失敗。intent 只能來自文件或註解，不能只在一般程式行貼標籤。未知或重複的靜態判定識別碼拒收。

## 執行狀態與重跑命令

既有 V8／Python 覆蓋檔逐一核對 SHA-256，並與來源清冊及情境計畫綁定。原因檔在 agent-api 有正覆蓋為「跑過」，只有 test-recording 為「只有測試跑過」，只有可讀來源為「只讀過程式」，否則「不知道」。有覆蓋不等於整個功能通過；來源已變的覆蓋不套用到新碼。寫入收據只代表隔離根的觀測。

靜態維修建議的測試取自單一 V8 程序中的單一測試入口，且真的涵蓋修改檔，並有已觀測的 node --test 命令。多測試入口不交叉歸因。建置程式的覆蓋不算每個測試都涵蓋。找不到就寫「沒有測試涵蓋」。

執行失敗的重跑以失敗測試位置為入口，將名稱轉義後使用 --test-name-pattern 選取代表測試；沒有測試入口時保留可移植的原情境命令。情境輔助程式須隨副本提供。命令路徑相對 repo 根目錄；專案外的絕對路徑不偽裝成可移植命令。

「在你的副本重跑」使用 PowerShell 單引號規則，內部單引號加倍；Markdown 顯示真引號，HTML 的文字節點也保留真引號。HTML 的小於、大於與 & 仍作必要編碼，複製 DOM 文字取得原值。命令與錯誤訊息經明確標記，不把原始技術文字刪成難以辨識的句子。

前置條件包括專案實際建置步驟、鎖定檔依賴、禁用安裝腳本、移除金鑰、離線及外部替身；維持需求單隔離執行邊界。命令清單不是新增授權。「原始執行紀錄」連到 evidence，保留當時絕對路徑，清楚標示為歷史記錄。

## 證據、大小與相容性

完整 stdout／stderr 及觀測、判決、清理記錄只寫入 evidence/run-<SHA-256>.json。識別碼由保留內容計算，同一記錄重複引用只存一份；SHA-256 是完整性識別，不是獨立佐證。原錄帶檔仍是外部來源，不複製整份巢狀錄帶到每張卡片。

health.json 保留舊 stats、issues、groups、blocks、links、limitations、sourceReads，新增維修單摘要、失敗列、關聯及 evidence 參照，不放完整 TAP。卡片的觀測只留執行識別碼與匹配檔案。report.md 主體只有維修單與 JSON／證據連結，目標小於 200 KB；大量不同故障仍可能超標，交付時要量測，不能截掉故障湊大小。

HTML 保留原技術報告展開區；Markdown 不再嵌入整份舊報告與每卡 JSON。舊文字連結重定位仍由 renderLegacyMarkdown 的相容性檢查覆蓋。流程圖與路線動態圖不改；體檢卡也採用有上限的分組。

主畫面繁中敘述不放英文 JSON 欄位或 :UNKNOWN；檔名、明確標記的命令、原始錯誤及穩定識別碼保留原字。禁用詞檢查只豁免這些必須可核對的內容。維修單不是完整故障偵測器；後續盲測與業務驗收仍須獨立進行。

阻擋點亦屬宣告對照：提供政策清單與 reason／關鍵字表，分底線、要處理、不確定；無宣告只列清單，防呆與混合條件不硬判。設定、錨點與限制見[阻擋點](stop-sites.md)。

## 1.21.0 顯示與宣告排除

報告按「同判定、同原因、同檔案」合併，每類預設顯示 20 組，先列正式路線，再按件數排序。每組附件數、出現處數與前三個錨點；不確定按呼叫端合約、執行證據、觸發條件等缺口分小類。省略組數明列，完整清單只放 JSON，不改「壞了」計數與原判定。

`maintenance.count` 與 `counts` 仍是原維修項目數；`occurrences` 是所附站點或觀測數。`maintenance.display` 另列顯示組數、省略數、小類統計與對回 `items` 的 indices。顯示合併不代表共同根因。修法句保留技術詞，缺值使用完整的查證句子。

~~~json
{
  "display": {
    "maxGroupsPerCategory": 20
  },
  "unusedExclusions": {
    "conventionLoaded": [
      "plugins/**/hook.py"
    ],
    "staticDirectories": [
      "public"
    ],
    "historyDirectories": [
      "archive"
    ]
  }
}
~~~

排除只套用於原本「沒人用」的候選，不影響正式閉包、斷線或測試分類。重疊宣告只計一檔，`unusedExclusions.excluded` 保留所有命中樣式，`stats.declaredExcluded` 另列數量。路徑使用 repo 相對路徑與 `/`，不接受絕對路徑或 `..`；目錄欄位不接受 glob。無預設專案名單，宣告不證明實際載入。
