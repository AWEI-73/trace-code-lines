# 四本查線劇本

依情境選一路；每次只讀步進器印出的當前步驟。步驟正本在 [資料檔](../assets/playbooks.json)，不要把整本載進上下文。

- `symptom`：錯誤、錯值、很慢或應該發生卻沒發生。交出原因、證據、修法方向、同類問題與未知的鏈卡。
- `takeover`：需要快速掌握陌生儲存庫的底。交出先讀五檔、不可信處、前五風險與未知的接手鏈卡。
- `change`：改、刪、搬、改名或改資料形狀之前。交出影響、同步修改處、重跑入口與舊記錄相容性的變更鏈卡。
- `integrate`：需要一次說清介面、安全及框架轉接邊界。交出可接／有條件可接／不建議、條件與未知的接入鏈卡。

## 用法

```text
node scripts/trace.mjs start --mode symptom --question "一句問題" --root <repo> --out <卡片.json>
node scripts/trace.mjs next --card <卡片.json>
node scripts/trace.mjs status --card <卡片.json>
```

用 `trace.mjs fill --card <卡> --step <n> --note "說明" --anchor "檔:行:文字"` 寫回當步並核對；可重複錨點，之後直接印下一步。
跳過加 `--skip` 並填說明；跳過不算取得證據。未開始步驟不提醒缺錨點；完成但缺錨點、跳過卻無說明與錨點才提醒。
錨點可同時放進對應章節；章節用法見 [鏈卡](chain-card.md)。未知的交代與補查邊界見 [對策表](unknown-playbook.md)。
填卡的章節與接入參數見 [接入分診](integrate.md)；同一步重送會追加內容，必要時先讀卡避免重複。
所有提醒只標示；只要卡片仍是可讀的有效 JSON，就不因缺項或跳步失敗。新情境只增資料檔的 modes 與 steps。
全部走完依印出的命令產卡；產卡保留情境與步驟。歷史工具輸出 JSON，提交雜湊是歷史錨點；共同改動比例的分母是含目標且不超過 30 檔的提交。
git 拒讀時保留未知；僅在獲明確授權時用 --safe-directory <repo> 於該次命令指定信任，不改設定。
原碼已前進時，症狀搜尋與歷史工具可加 `--rev <提交>` 固定舊版；鏈卡應讀核對過雜湊的該版原碼副本。
寫入者只是詞法候選，註解與字串也可能命中；共同改動不證明呼叫或因果，改名以各路徑分開計數。

## 通則十條

1. 先確定哪一份在跑，再讀任何碼。 已安裝的、已部署的、checkout 的，常常是三個版本。讀錯份，後面全錯。
2. 先讀記錄，再讀碼。 記錄說「發生了什麼」，程式說「可能發生什麼」。答案常常已經在記錄裡。
3. 從終點往回走。 從錯的輸出、缺的檔、發生的副作用，找誰寫的，再找誰叫它。從入口往前走會迷路。
4. 每跳一站留一個錨點（檔、行、該行應有的字）。沒有錨點的那一跳是推論，要標出來。
5. 三層分開講：文件說有／程式做得到／記錄裡真的有。不要拿其中一層去斷言另一層。
6. 負面結論要附搜尋範圍。「沒有」的意思是「在這些檔、用這個樣式，找到 0 筆」。
7. 成本階梯，由低往高：讀記錄 → 搜字面 → 讀那個函式 → 靜態工具 → 隔離試跑 → 付費或真帳號（要授權）。前一階答得了就不往上。
8. 假說要過一次反證：「如果原因是 X，那另一處一定看得到 Y。」去看 Y。看到才寫成原因，看不到就換下一個。
9. 報類別，不報單點。 找到一個漏接，問同一種寫法還有哪裡。
10. 未知要交代：哪一類、為什麼不知道、試過什麼、怎樣才會知道、目前最好的解釋。見 unknown-playbook。

## 常見原因（依序懷疑）

1. 跑的不是你讀的那一份（舊版、舊部署、快取、沒重啟的常駐程序）。
2. 中間有一層只挑部分欄位往外給（白名單、投影、摘要），新欄位被丟掉。
3. 同一份清單有兩處，只改了一處（登記表、manifest、釘選檔、發版清單）。
4. 守門條件用字串比對，文字改了就不成立；或提示詞裡的一句限制讓模型從不走那條路。
5. 預設值把缺值蓋掉，看起來正常其實沒收到。
6. 例外被吞掉，後面拿到空值繼續跑。
7. 快取或快照的新舊判定錯。
8. 環境：編碼、長路徑、暫存位置、被清掉的環境變數、權限。
9. 幾個時限設成同一個值，逾時時回報的原因是錯的那一個。
10. 路徑或名稱被當成資料存在記錄裡，改名後舊資料讀不回來。
